# Literature positioning (one focused pass, 2026-11-23; abstracts only, not full papers)

**Already solved.** Query-aware temporal re-ranking with interval or recency signals: [Q-TIE](https://arxiv.org/pdf/2609.23880) maps a query's temporal constraint to a start-end interval and scores it; [Re3](https://arxiv.org/abs/2509.01306) (v1 citable; v2 listed as withdrawn) gates relevance against recency; [IA-RAG](https://arxiv.org/abs/2606.06044) uses Allen interval relations over event units with fuzzy-boundary tightening; [FRESCO](https://arxiv.org/pdf/2604.14227) targets evolving semantic conflict. Bitemporal memory stores for agents/graph RAG exist (Graphiti docs; post-graph-rag arXiv 2608.24921; a graph-native bitemporal memory store arXiv 2607.26520) and separate "valid at T" from "known as of T" at the storage/query layer.

**Remains.** I found no retrieval *ranking* paper or benchmark that (a) defines the query's information horizon h separately from target time t, (b) evaluates the four intents (current / valid-at / known-at / valid-known) on naturally versioned authoritative documents, and (c) measures how often single-clock rankers return evidence inadmissible under the requested semantics. A legal-RAG position paper (arXiv 2606.09724) argues for bitemporal modeling but, from the snippet, is not a ranking evaluation. This is a search-snippet judgment; read the full text of the bitemporal graph papers and the legal paper before claiming the gap.

**Strongest affordable baseline.** B6 (soft temporal-distance on publication time, a TimelyRAG-style approximation) plus a single-clock cutoff. A faithful Q-TIE run (code: github.com/ssoy0701/Q-TIE) is the right stronger baseline; it models an interval for t but not h, so expected to fail on known-at and valid-known. Official repo unavailable (404, 2026-11-23); shipped as a labelled Q-TIE-style stand-in built from the abstract, not a reproduction.

**What convinces a reviewer.** (1) Human-judged relevance, not metadata-derived gold; (2) natural queries from people other than the method authors; (3) Q-TIE and one learned/LLM router baseline; (4) held-out document families with cluster CIs; (5) an honest statement that eligibility is a deterministic bitemporal filter and the contribution is the problem definition, evaluation resource and failure analysis.

## Update after reading full texts (A9, 2026-11-23)
Read from the PDFs (text extracted locally): Q-TIE (2609.23880), IA-RAG (2606.06044), the legal-RAG paper (2606.09724), the bitemporal memory store (2607.26520). Not read: TEMPS, HoH, MRAG, TimeR4, PAT-Questions, WikiRecentChanges, Re3 body, FRESCO body.

- **Q-TIE is stronger than my stand-in.** It extracts query intervals including one-sided types and evaluates per-type results for "as of" (246 queries), "by", "before", "after", "between", "from", "in" on Nobel Prize (989 docs/3,244 queries) and TempRAGEval (9,695 docs/883 queries); baselines include TempRALM, MRAG, TimeR4. Its document side is a document time, not a separate publication vs valid clock, and I found no information-horizon or "known by" semantics in what I read. So the correct reading of our Q-TIE-style results: the point-interval stand-in (0.30 top-1) is *too weak*; the better approximations of a one-sided-interval method with a single document clock are our hard-cutoff baselines B2 (publication clock) and B3 (effective clock) (0.30 and 0.33 on test3), which each fail on the other intent. The claim "a single document clock fails when the query semantics concern the other clock" stands; the claim "Q-TIE would behave like B6" does not. Ask the authors for code/predictions or run it on our data if released.
- **Legal paper (de Martim 2026)** argues bitemporal correctness for legal retrieval (vacatio legis, retroactive provisions, corrigenda; valid vs transaction time "rarely exposed as a first-class retrieval capability"); it is an argument/research agenda with an evaluation checklist, not (as far as I read) a ranking benchmark. It is the closest conceptual prior art: our contribution cannot be "legal retrieval needs two clocks"; it is an empirical measurement of how often single-clock rankers fail and by how much, a (t, h, intent) query formulation, and an open resource on a real versioned corpus.
- **Bitemporal memory store (2607.26520)** already implements valid-time and transaction-time post-filtering of vector hits (an `as_of_semantic_search` with valid_at; evaluated on LongMemEval for memory). So hard bitemporal eligibility is existing database practice. Do not present eligibility as novel; the open pieces are intent routing from natural language and ranking evaluation on authoritative document histories.
- **IA-RAG**: intervals and Allen relations over event units; no publication/horizon distinction found in the text I read.

**Revised novelty statement.** Not the model. The defensible contribution is (1) the (t, h, intent) formulation for evidence retrieval; (2) a measured demonstration, on a verified real-world versioned corpus, that single-clock methods (cutoff, soft distance, recency gate, interval-style) return inadmissible evidence for 16-55% of queries and that routed two-clock eligibility removes this; (3) the resource and annotation protocol. Risk: reviewers may see this as engineering unless human-annotated queries and a real Q-TIE comparison are added.

**A9b partial (2026-11-23, search snippet only, not full text):** [TEMPS](https://arxiv.org/pdf/2609.28048) (listed as EMNLP 2026; venue and ID from secondary pages, verify) adds a temporal branch to a frozen dense retriever: each text with its anchor date maps to a diagonal Gaussian over time, scored by KL; reports MRR gains and R@1 19.92 -> 25.39 on TS-Retriever. Anchor date = single document time, so it falls in the same single-clock family as Q-TIE/TempRALM; MIT-licensed code on Hugging Face (aldebaran-research/temps) could serve as a frozen-embedding baseline if the corpus anchors are set to publication date vs effective date (a cheap two-variant comparison, not yet run). Still unread: HoH, MRAG, TimeR4, PAT-Questions, WikiRecentChanges, Re3 and FRESCO bodies.
